# Katana Bot

Telegram-бот для модерации групп и комментариев под постами каналов. Администраторы могут удалять сообщения командой и включать автоматическое удаление ссылок отдельно для каждой группы.

[![aiogram 3](https://img.shields.io/badge/aiogram-3-009CFB)](https://docs.aiogram.dev/)

## Возможности

- Удаление сообщений и комментариев командой `/del` в ответ на нужное сообщение.
- Жалобы на сообщения и комментарии с просмотром последних обращений в личном чате администратора с ботом.
- Фильтр обычных и скрытых ссылок в новых и отредактированных сообщениях, включая подписи к медиа.
- Словарный фильтр мата на русском и английском с журналом срабатываний и опциональным удалением.
- Ручной бан и разбан, а также опциональный автобан за повторные нарушения в супергруппе.
- Настройки фильтра сохраняются в SQLite отдельно для каждой группы и переживают перезапуск.
- Ссылки администраторов пропускаются. Автоматически пересланные посты канала защищены от удаления ботом, чтобы сохранить ветки комментариев.

## Быстрый старт

Понадобятся Git и Python 3.13. Команды ниже подходят для macOS и Linux.

```bash
git clone https://github.com/livej0urnal/katana-bot.git
cd katana-bot
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp -n .env.example .env
```

1. Создайте бота через [@BotFather](https://t.me/BotFather) командой `/newbot` и впишите полученный токен в локальный файл `.env`.

   ```dotenv
   BOT_TOKEN=ваш_токен_от_BotFather
   ```

2. Добавьте бота в группу и назначьте администратором с правом **«Удаление сообщений»**.
3. Для комментариев под постами привяжите группу через **Настройки канала → Обсуждение** и выдайте боту право в этой группе. Фильтр будет действовать на комментарии и обычные сообщения группы.
4. Запустите бота.

   ```bash
   .venv/bin/python main.py
   ```

   В PyCharm выберите интерпретатор из `.venv` и запустите `main.py`. Бот получает обновления через long polling. Для одного токена достаточно одного запущенного процесса.

5. Отправьте `/settings` в группе от имени администратора. Бот покажет текущие правила и проверит права на удаление сообщений и блокировку участников.

## Команды

| Команда | Кто может использовать | Действие |
| --- | --- | --- |
| `/katana` | Участники группы | Справка и состояние фильтра ссылок |
| `/start`, `/help` | Все | Инструкция в личном чате или список команд в группе |
| `/settings` | Администраторы | Текущие настройки группы и права бота |
| `/links on` | Администраторы | Включить фильтр ссылок в текущей группе |
| `/links off` | Администраторы | Выключить фильтр ссылок в текущей группе |
| `/del` | Администраторы | Удалить сообщение, на которое отправлен ответ с командой |
| `/report` | Участники группы | Пожаловаться на сообщение или комментарий, ответив на него |
| `/reports` | Администраторы | Получить в личку жалобы на последние 10 сообщений, на которые пожаловались |
| `/profanity log` | Администраторы | Записывать срабатывания фильтра мата в журнал приложения |
| `/profanity delete` | Администраторы | Удалять сообщения с распознанным матом |
| `/profanity off` | Администраторы | Выключить фильтр мата |
| `/ban` | Администраторы | Забанить автора сообщения, ответив на него |
| `/unban ID` | Администраторы | Разрешить забаненному пользователю снова вступить |
| `/autoban on` | Администраторы | Банить после трёх удалённых за мат сообщений одного пользователя за 24 часа |
| `/autoban off` | Администраторы | Выключить автобан и очистить счётчики группы |

Фильтр ссылок по умолчанию выключен. Для проверки после `/links on` отправьте `https://example.com` от обычного участника. Для проверки редактирования добавьте ссылку в уже отправленное тестовое сообщение.

Фильтр мата тоже выключен по умолчанию и настраивается отдельно для каждой группы. Начните с `/profanity log` и отправьте новые примеры от обычного участника. В журнале процесса будут идентификаторы группы и сообщения без текста. Фильтр проверяет известные словарные формы в тексте и подписях к медиа, включая редактирование. Он пропускает сообщения администраторов и автопересылки постов из канала.

Для банов выдайте боту право **«Блокировка пользователей»**. Для автобана в супергруппе сначала включите `/profanity delete`, затем `/autoban on`. Баны бессрочные до разбана. Бот пишет ID в уведомлении о бане. После разбана пользователь может вступить заново по ссылке. Автобан по умолчанию выключен. Ссылки и жалобы не начисляют нарушения для /autoban. Отдельный режим Katana Strike учитывает автоматические удаления.

Жалобы сохраняются в базе данных вместе с идентификаторами отправителя и сообщения и фрагментом текста до 120 символов. Повторная жалоба того же участника на то же сообщение учитывается один раз. Для просмотра откройте личный чат с ботом, нажмите **Start**, затем отправьте `/reports` в нужной группе от своего аккаунта. Жалоба сама по себе не удаляет сообщение.

```bash
.venv/bin/python -m unittest discover -s tests -v
```

GitHub Actions запускает тесты при каждом push и pull request. Тесты используют временную базу в памяти и подменяют обращения к Telegram. Токен для CI не нужен.

Рабочая база `katana.sqlite3` создаётся рядом с `main.py`. Файл `.env` и рабочая база исключены из Git.

## PostgreSQL и перенос данных

При пустом `DATABASE_URL` бот продолжает работать с SQLite. Для PostgreSQL используется драйвер psycopg через SQLAlchemy 2, а схему создаёт Alembic.

1. Остановите бота в PyCharm. Установите новые зависимости и добавьте в существующий `.env` следующие параметры, сохранив `BOT_TOKEN`. Замените `YOUR_LOCAL_PASSWORD` одним и тем же локальным паролем в обеих строках. Для примера подойдёт пароль из букв и цифр. Спецсимволы в URL нужно кодировать.

   ```dotenv
   POSTGRES_PASSWORD=YOUR_LOCAL_PASSWORD
   DATABASE_URL=postgresql+psycopg://katana:YOUR_LOCAL_PASSWORD@127.0.0.1:5433/katana
   ```

2. Запустите Docker Desktop, затем выполните команды из папки проекта.

   ```bash
   .venv/bin/python -m pip install -r requirements.txt
   docker compose up -d --wait postgres
   .venv/bin/python -m alembic upgrade head
   ```

3. Для переноса с SQLite запустите импорт один раз до первого запуска бота с PostgreSQL.

   ```bash
   .venv/bin/python import_sqlite.py katana.sqlite3
   ```

   Импорт читает SQLite без записи, переносит реестр групп, фильтры, жалобы, счётчики, белые списки, журнал, репутацию и объявления и печатает количество строк по каждой таблице. Целевая база должна быть пустой. Исходный файл остаётся на месте.

4. Запустите `main.py` и проверьте `/settings` и `/reports` в тестовой группе. Чтобы вернуться к SQLite, остановите бота и очистите `DATABASE_URL`. Изменения, сделанные после переключения в PostgreSQL, в SQLite автоматически не появятся.

## Расширенная модерация

| Команда | Действие |
| --- | --- |
| `/protect flood on` | Удалять сообщение при 6 сообщениях или 3 повторах от одного автора за 10 секунд |
| `/allow add domain example.com` | Разрешить домен и его поддомены в фильтре ссылок |
| `/allow add user ID` | Исключить пользователя из автоматической модерации и проверки новичков |
| `/protect gate on` | Попросить нового участника решить пример кнопкой. Ограничение Telegram истекает через 10 минут |
| `/protect raid on` | Включать проверку новичков на 5 минут при 6 вступлениях или 6 удалениях за спам за минуту |
| `/protect comments strict` | Блокировать ссылки в распознанных ветках обсуждений, даже если общий фильтр выключен |
| `/protect comments off` | Пропускать автоматическую модерацию в распознанных комментариях |
| `/warn [причина]`, `/mute МИНУТЫ [причина]`, `/tempban МИНУТЫ [причина]` | Применить действие ответом на сообщение |
| `/unmute` | Снять ограничение ответом на сообщение участника |
| `/protect strike on` | За 3 балла мут на час, за 5 — на сутки, за 10 — бан. Балл начисляется за предупреждение или автоматическое удаление и истекает через 24 часа |
| `/protect shadow on` | Оставлять автоматические санкции в журнале без публичных уведомлений |
| `/audit`, `/stats` | Получить последние действия или их счётчики в личный чат |
| `/appeal ID_ГРУППЫ НОМЕР_ДЕЙСТВИЯ ПРИЧИНА` | Отправить в личном чате обжалование своей санкции. Оно появится в журнале группы |
| `/thanks`, `/rep` | Поблагодарить автора ответом или посмотреть репутацию |
| `/announce МИНУТЫ ТЕКСТ`, `/announce off` | Настроить или выключить одно периодическое объявление на группу |

`/allow remove` удаляет исключение. Режимы защиты включаются отдельно для каждой группы. Для комментариев `inherit` возвращает общие правила. Настройки доступны через `/settings`, где администратор также может переключать антифлуд и Shadow Mode кнопками.

Katana Strike и автобан за мат — два режима эскалации. При активном Katana Strike за автоматические удаления применяется его шкала. Администраторские команды и выдача ограничений требуют соответствующих прав Telegram.

По умолчанию короткие окна антифлуда и антирейда хранятся в памяти процесса. Для Redis установите `requirements-redis.txt`, запустите `docker compose --profile cache up -d redis` и укажите `REDIS_URL=redis://127.0.0.1:6380/0` в `.env`.

### ML-антиспам и модели Ollama

- `/protect newspam log` включает предварительный RU/EN-классификатор для участников в первые сутки после вступления. Он обучен на небольшом синтетическом наборе. Режим `delete` стоит проверять на собственных примерах.
- Укажите `OLLAMA_URL`, `OLLAMA_TEXT_MODEL` и при необходимости `OLLAMA_VISION_MODEL` в `.env`. Сервис должен быть доступен процессу бота. Для изображений нужна модель с поддержкой vision.
- `/protect ai log` проверяет текст на спам, рекламу, мошенничество, оскорбления и токсичность. До четырёх предыдущих реплик для контекста хранятся в памяти отдельно по группе и ветке.
- `/protect nsfw log` проверяет доступные боту фотографии в чате. `/protect profile log` проверяет последнее доступное фото профиля при вступлении. В режиме `delete` для профиля бот может удалить до пяти недавних сообщений пользователя, которые видел сам за последние 10 минут.
- Все четыре команды принимают `log`, `delete` и `off`. После включения AI соответствующий текст или изображение передаётся на настроенный адрес Ollama. При недоступности модели бот продолжает применять локальные правила.

### Веб-панель

Панель показывает до 200 зарегистрированных групп, статус бота и счётчики действий. Для запуска задайте `DASHBOARD_PASSWORD` в `.env`.

```bash
.venv/bin/python -m pip install -r requirements-dashboard.txt
.venv/bin/python -m uvicorn dashboard:app --host 127.0.0.1 --port 8000
```

Откройте [локальную панель](http://127.0.0.1:8000/) и войдите как `admin` для обзора групп. Этот доступ предназначен для владельца установки.

Для доступа администратора отдельной группы задайте один и тот же случайный `DASHBOARD_SESSION_SECRET` в окружении бота и панели. Нажмите Start в личном чате с ботом, отправьте `/panel` в группе, затем введите полученный код на [странице входа](http://127.0.0.1:8000/login). Код действует 5 минут, сессия — 30 минут. Панель проверяет права в Telegram при каждом запросе и позволяет переключать антифлуд и Shadow Mode для выбранной группы. Остальные настройки доступны командами Telegram. Для доступа по сети используйте HTTPS.

## Сквозные проверки локальных сервисов

В обычном терминале macOS с доступом к Docker Desktop запустите:

```bash
./scripts/test-local.sh
# Дополнительно скачать модель Ollama и проверить запросы с текстом и изображением
./scripts/test-local.sh --with-ollama
```

Скрипт запускает сервисы в отдельном Compose-проекте `katana-qa`, создаёт отдельную тестовую базу PostgreSQL, применяет миграции и выполняет проверки PostgreSQL, Redis и веб-панели. Параметр `--with-ollama` добавляет проверку модели на искусственном тексте и изображении. Для запуска должны быть свободны локальные порты 5433 и 6380, а для Ollama также 11434. Рабочие `.env` и `katana.sqlite3` остаются на месте. Контейнеры остаются запущенными для повторной проверки, а временная база удаляется после тестов.
